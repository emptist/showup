<objective>
The evening the coworker remembers: run one script, type one password, and from then on the Mac wakes itself, the window appears on time, ringing and holding happen in the user's own session — and changing the times later needs no password at all.

Purpose: this is the phase the whole redesign was argued for. It also carries the *only* sudo in the entire system, and the only blocking real-machine verification.

Output: installer script (+ uninstall), the root daemon plist, the user agent plist, a stamped daemon, and a README install section a coworker can follow blind.

<what-installs-where> (the coworker's map)

    ONE PASSWORD, at install
      make install-session APP=<app> TIMES=4:00,8:00
      └─ sudo Scripts/install-session.sh            ← the only sudo, ever
           ├─ make release; copy binary + stamp → /usr/local/bin (root)
           ├─ write /Library/LaunchDaemons/com.<label>.showup-renew.plist (root)
           │     RunAtLoad=false; StartCalendarInterval = daily 00:05;
           │     the program argument is: showup renew        (root)
           ├─ sudo launchctl bootstrap system <plist>; first renew runs at once
           │     (tonight's moments armed before the machine sleeps)
           └─ writes nothing else as root

    NO PASSWORD, from then on (user side of the same script)
      ├─ write ~/Library/LaunchAgents/com.<label>.showup.plist (no sudo)
      │     StartCalendarInterval = the requested times; program: showup
      ├─ launchctl bootstrap gui/<uid> (no sudo)
      ├─ contract file written by the run itself (01/02-01)
      └─ later changes: rerun `showup -a X -t ...` (user) → contract updated;
         the next renewal picks it up. No sudo. THE POINT.

  Nightly, forever after:
      00:05  daemon (root, 2 s): cancel own stale → arm owed moments → exit
      T      agent (user): ring first / hold the moment / wait for the person /
             open -a in own session / log to ~/Library/Logs/showup
</what-installs-where>

  <action>
    `install-session.sh`: guarded steps, each printing what it did with grounded paths; refuses partial truth (fails loudly between steps with what is already true — the log's tone). Stamp: the daemon's binary copy gets the same stamp logic as `make install` (03-01 widens this further). Idempotent: rerunning updates in place, cancels-own then re-arms.
    `uninstall-session.sh` (no sudo for user items; the same sudo once for its root side): bootout daemon + agent, remove plists + binary + stamped ground, cancel owns (root, tagged), leave `/var/log` legacy logs to the 7-day rule if they exist.
    The plist's program argument is `/usr/local/bin/showup renew`, `StandardErrorPath` into the user ground's log dir (daemon also logs into the same visible place — one log, one story).
    Avoid: any sudoers file; any SMAppService/SMJobBless call (that's app-bundle packaging, out of scope); `pmset` writes from the installer (the daemon's IOPM act is the disciplined one).
  </action>
  <verify>`shellcheck` the scripts; a sandbox round trip: install-session → `launchctl print system/com.<label>.showup-renew` shows the daemon; `launchctl print gui/$(id -u)` shows the agent; uninstall-session leaves: zero labeled daemons/agents, zero armed owned wakes (`pmset -g sched` shows none of the tag), no binary.</verify>
